## Relationship Semantics

- `Required`: the feature should not be generated without this foundation or an equivalent custom controller.
- `Recommended`: improves robustness or normal UX, but can be skipped for a smaller scope.
- `Optional`: add only when requested by the user or when a downstream feature needs it.
- `Conflicts / sequencing`: state or ordering constraints to enforce when composing modules.

The graph preserves flexibility: satisfy dependencies by capability, not by demo module identity. For example, a custom `MeisheTimelineController` can satisfy `engine-meishe` if it initializes the same timeline/track/clip API graph and lifecycle guards.

| Layer | Modules | Purpose |
| --- | --- | --- |

| P0 timeline core | `engine-meishe` or equivalent custom controller | Timeline creation, track/clip graph, timeline data reconstruction. |
| P0/P1 editor product flow | `selectmedia`, `edit`, `edit-clipedit`, `edit-caption`, `edit-filter`, `edit-animatesticker`, `edit-transition`, `edit-music`, `edit-record`, `edit-watermark`, `edit-background`, `edit-mask`, `edit-makeup` | Media import, ratio setup, live preview editor, child tools, and export. |
| P1 common workflows | `capture`, `cutsame-template`, `mimodemo` | Normal camera/template workflows. |
| P2/P3 feature extensions | caption/sticker/filter/audio/AR/template/preview/export modules | Load only for requested features or exact API hits. |

## Device-Validated Short-Video Editor Chain

For a real short-video editor, use this chain before reading the historical matrix below:

```text
app-root/base-meishe/utils
-> sdk runtime init and first-run resource copy/check
-> asset-manager init
-> feature hub
-> selectmedia or equivalent media import
-> ratio/resolution selection
-> TimelineData-style state store
-> TimelineUtil-style timeline build/rebuild
-> VideoFragment-style NvsLiveWindow binding
-> playback/seek callbacks and overlay coordinate mapping
-> requested editor child modules
-> apply/rebuild affected timeline sections and refresh live window
-> compile/export
```

When this section conflicts with the auto-generated table, this section wins for editor products:

- `selectmedia` is P0/P1 for short-video editing even though its direct SDK call count is low. It owns media selection, AV metadata validation, ratio selection, and timeline seed state.
- `edit` is the core editor shell, not a caption/sticker feature. It owns the timeline, live preview fragment, toolbar child-module routing, child result handling, and export entry.
- `edit-clipedit` is the clip-edit child module under `edit`; it should not be grouped as a generic caption/sticker dependency.
- Filter, sticker, caption, compound caption, animation, mask, background, watermark, transition, music, voiceover, beauty, and makeup are editor child modules unless the user explicitly asks for API-only snippets.
- The material center is a service bound to child modules by package type/category. It should appear where filters, captions, stickers, transitions, makeup, AR, or templates need downloadable packages.

## Composition Rules

1. For a broad app, load P0 modules first, then P1 workflows, then only requested P2/P3 extensions.
2. For a narrow custom feature, do not copy the whole demo module; pull the minimum required category rules and API graph nodes.
3. When two modules both require the same foundation, share one generated controller/manager instead of duplicating initialization.
4. Treat `recommended` dependencies as quality gates: include them when they affect user-visible reliability, omit them for tiny proof-of-concept code.
5. Treat `optional` dependencies as user-choice surfaces: add controls/assets only when the request mentions them.
6. Always apply API graph conflicts across module boundaries, especially playback/capture/compile/structural edit interactions.
