This reference describes demo-proven API ordering for complete feature blocks. Use it when composing new features or generating a project, after selecting APIs from `demo-api-list.md` and constraints from `demo-api-constraint-map.md`.

## Composition Rules

- Always initialize SDK/context before loading assets or creating timelines.
- Keep capture and timeline playback/export flows separate unless the feature explicitly bridges them.
- Stop playback/capture before destructive timeline changes, asset replacement, compile/export, or Activity teardown.
- Treat SDK object factories/adders as nullable unless official docs guarantee otherwise.
- Treat boolean-return APIs as start/success gates and report failure through UI/log/callback.
- Use callbacks for long-running operations: capture device/recording, playback/seek, asset package install, media convertor, and compile/export.
- Keep time units in microseconds for timeline in/out/duration APIs.
- Keep effect parameter setters typed; do not pass string values into numeric/bool/color setters.
- Prefer source-specific controllers: capture controller, timeline controller, asset installer, effect controller, export controller.
